# 푸시 클릭 복구 검수 — v2.47.4

- 문제: 실기기에서 푸시를 누르면 앱만 열리고 클릭한 알림 팝업이 나타나지 않는 사용자 보고. 사용자는 iOS 홈 화면 앱, 대표님 기기는 Android.
- 기존 코드의 확인된 빈틈: 시작 중인 앱에 보낸 일회성 메시지의 수신 확인·보관이 없었음. `navigate()` 또는 `openWindow()`가 목적지를 반영하지 못하면 앱 시작 후 복구 불가.
- 플랫폼 참고: [WebKit 263687](https://bugs.webkit.org/show_bug.cgi?id=263687), [WebKit 252544](https://bugs.webkit.org/show_bug.cgi?id=252544). 보고된 기기의 OS 버전이나 정확한 실패 API를 원격으로 확인한 것은 아님. 과거 Android `navigate() === null` 설명은 실기기 근거가 없었음.

## 변경

서비스워커가 클릭 목적지 URL·클릭 ID·시각만 별도 CacheStorage에 10분간 보관한다. 알림 본문·인증 토큰은 저장하지 않는다. 앱은 인증 및 SW 준비 후, 포커스·화면 복귀·controller 변경 시 보관된 목적지를 가져와 라우팅하고 수신 확인한다. 이전 클릭 확인이 새 클릭을 지우지 않도록 저장소 작업을 직렬화한다. 학생·공개 창은 대상에서 제외한다.

숨겨진 강사 탭도 클릭 정보를 소비하지 않는다. 직접 클릭보다 먼저 요청된 지연 응답과 오래된 클릭 시각은 최신 목적지를 덮지 못한다. 앱이 클릭 기록보다 먼저 시작해 빈 응답을 받는 경우에는 시작·복귀 후 최대 5초간 500ms 간격으로 로컬 SW를 재조회하고, 수락 즉시 중단한다.

팝업은 내용 조회 중·실패·알림 없음 상태도 안내한다. 닫을 때 URL의 선택 ID를 제거해 같은 알림의 새 클릭도 다시 열린다. 본문 줄바꿈은 유지한다.

## 실제 브라우저 검수 범위

- 격리된 Chrome 152, 로컬 production preview `http://localhost:5180`, 실제 빌드 `sw.js` 등록.
- 모든 외부 요청은 합성 fixture로 응답. 실제 Notion 쓰기·푸시 전송 없음. 운영 로그인이나 인증 우회 없음.
- `02_devtools/qa-push-click.mjs`로 실제 SW 이벤트 핸들러에 합성 클릭 이벤트를 전달하고, `openWindow()`가 null/홈 진입으로 이어지는 상황과 기존 창 `navigate()` 거부를 재현.
- 앱 미실행/초기 메시지 유실 → 홈 재진입 → 해당 팝업 및 전체 본문 표시 → 수신 확인 후 클릭 기록 삭제: 통과.
- 이미 열린 앱의 주소 이동 실패, 같은 알림 닫기 후 재클릭, 로그인 완료 후 목적지 복원: 통과.
- 390×844 모바일/1440×1000 데스크톱 팝업, 320×640 긴 본문 스크롤: 가로 넘침 없음, 마지막 본문과 닫기 접근 가능. 앱 JS 오류 0.
- 이미지: `mobile-dialog.png`, `desktop-dialog.png`, `mobile-inbox.png`, `mobile-long-bottom.png`.

이 검수는 실제 iPhone/Android OS의 푸시 탭을 대신하지 않는다. 설치된 앱 업데이트 후 실기기 확인이 별도로 필요하다. 일반 Vite dev 서버는 SW 등록이 비활성이므로 production preview로 검수한다. 기존 `localhost:5173`은 이전 루트 작업 트리여서 이번 팝업 수정본 검수 주소가 아니다.
