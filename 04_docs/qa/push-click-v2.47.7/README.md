# 실기기 푸시 처리 진단 — v2.47.7

v2.47.6의 실제 iOS27 백그라운드 클릭(run34322173427)도 팝업이 안 뜬다는 사용자 확인을 받았다. 따라서 이전 자동 검수로 실기기 문제가 해결됐다고 결론 내리지 않는다.

이번 변경은 동작을 추측해 다시 바꾸는 대신 실제 기기의 처리 상태를 확인하기 위한 로컬 진단이다. 설정의 ‘알림 진단’에서 사용자가 확인·복사하며 자동 전송하지 않는다.

- 앱: 코드 버전, root/강사/공개 경로 분류, 알림 ID 존재 여부, 주소와 Router 일치 여부, 표시/인증/SW 준비 상태, 최근 동작 enum·시각. 세션 로컬 최대40건, 24시간 유효.
- SW: 처리 코드 버전, native navigate 지원 여부, 푸시 표시/클릭 이벤트/이동 오류 종류·시각, pending 존재·나이. 기기 CacheStorage 최대16건, 24시간 유효.
- 본문·제목·이름·실제 알림 ID·전체 URL·학생 경로·토큰·구독 endpoint·userAgent는 수집하지 않는다. 저장/반환 모두 허용 필드로 정제한다.
- 조회는 로컬 MessageChannel이며 최대1.5초 후 상태를 반환한다. 네트워크·구독·인증 변경 없음. 원본 오류 메시지는 표시하지 않는다.

## 검증

- 영향 테스트 80개 통과: 진단 수집 8개, 브리지 44개, Router 동기화 10개, SW 15개, 진단 UI 3개. SW 진단 조회가 만료 클릭 데이터를 삭제하지 않는 회귀 검사 포함.
- `npm run build` 성공(운영 Worker URL 지정), `npm run lint -- --quiet` 오류 0, 디자인 감사 ERROR 0 / WARN 0 / 기존 REVIEW 100. 기존 단어 CSV 중복 및 번들 크기 안내는 변경 범위 밖이다.
- `node 02_devtools/qa-push-click.mjs`: `http://localhost:5180` 실제 production 빌드와 SW를 격리 Chrome에서 실행했다. cold query / query 1회 소비 / 오래된 pending 우선순위 / Router 이벤트 없는 warm hash·query 복귀 / legacy 복구 / 동일 알림 재열기 / 로그인 복구 통과.
- 진단 UI에서 앱·SW 버전 2.47.7을 확인했고 fixture ID·학생 이름·인증값이 진단에서 제외됨을 검사했다. 모바일 320×640과 데스크톱 1440×1000의 복사·닫기 버튼이 가려지지 않는 것을 직접 이미지로 확인했다. 실제 외부 요청은 fixture로 차단했으며 알림은 발송하지 않았다.
- 브라우저 오류 0, 가로 넘침 없음, 긴 본문 팝업 스크롤 및 마지막 줄·닫기 버튼 확인. 증거: 이 폴더의 모바일/데스크톱 팝업·알림함·진단 화면 PNG 6개.

이 릴리스는 기기 내 진단 추가이며, 백그라운드 팝업 해결본이 아니다. 위 검수는 실제 iOS 알림센터 클릭을 대신하지 않는다. 실기기 진단 정보 확보 후 실패 지점에 맞춰 수정한다.
