# D-1 자정 지연 백업 실패 오탐 수정

## 확인한 원인

9/17~19 일일 요약의 학생·상담 각 1회 실패는 9/16~18 KST 자정 이후 실행된 전날 백업이다. 자동 실행 가드가 전날 성공을 조회하기 전에 발송 시작 시각 이전이라는 이유로 예외를 발생시켰다. 9/16~18 17시 본 작업은 학생 3·5·2건 접수, 실패/결과 불명 0건이며 상담 대상은 0건이었다. 접수 결과와 최종 수신 여부는 구분한다.

## 변경

- 발송 시작 전 자동 실행은 전날 17시부터 자정 직전까지 성공 이력을 확인한다. 성공이 있으면 정상 생략하며 Notion 조회·Solapi 발송·실패 알림을 하지 않는다.
- 성공 없음 또는 조회 불가는 실패로 유지한다. 오류는 전날 날짜와 성공 미확인/조회 불가를 설명하며 새벽 발송을 허용하지 않는다.
- 새벽 정상 생략은 당일 17시 이후 성공 조회에 포함되지 않아 저녁 본 작업을 막지 않는다.
- 아침 브리핑도 전날 17시 이후 성공만 인정하여 전전날의 지연 백업이 실제 미발송을 가리지 않게 한다.
- 서명 이력 시작 기록과 수신자별 중복 방지, 수동 재실행 경로는 유지한다. 과거 실패 기록을 삭제하거나 요약에서 숨기지 않는다.

## 검증 및 반영 상태

외부 통신을 차단한 가상 GitHub/Notion/Solapi/ntfy 응답으로 자정 경계, 다음날 16:59 지연, 과거/새벽 성공 제외, 조회 장애, 실제 미발송, 다음 저녁 발송, 아침 브리핑을 검증했다. notificationReminderScripts·notificationLedger·notificationAutomation 215개 테스트 통과. 최종 변경 후 notificationDailyBrief·notificationReminderScripts·notificationScheduler 89개 테스트 통과(앞선 실행과 중복 포함). 변경 스크립트 문법 검사 및 diff 공백 검사도 통과했다.

현재 체크아웃에 기존 미커밋 변경이 있으므로 이를 보존하여 필요한 부분만 수정했다. 운영 재실행·시험 발송·커밋·푸시는 수행하지 않았다. 운영 적용에는 GitHub 기본 브랜치 반영이 필요하며 PWA/Worker 배포는 필요하지 않다.
