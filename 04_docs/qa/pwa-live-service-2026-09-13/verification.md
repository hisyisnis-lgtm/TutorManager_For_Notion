## 환경과 한계

- 로컬 개발 서버: `http://127.0.0.1:5193`
- 실제 `pwa/dist` 미리보기: `http://127.0.0.1:5194`
- 격리된 Chrome 브라우저 컨텍스트에서 실제 로그인·OTP 화면을 사용하고, 서버 응답은 합성된 검수 데이터로 대체했다. 인증 저장소 직접 주입은 사용하지 않았다.
- 실제 운영 계정 로그인, 실제 OTP·알림 발송, Notion 데이터 수정, 동의서 제출, 결제·환불은 수행하지 않았다.
- 브라우저 MCP의 기존 프로필 잠금 때문에 별도의 Playwright Chrome 컨텍스트로 검수했다. 다른 사용 중인 브라우저는 종료하지 않았다.
- 이 기록은 배포 전 UI 검수 결과다. 배포 완료 여부와 운영 버전은 별도의 배포 기록을 따른다.

## 증거

- `phase1-browser-results.json`: 기록 저장·갱신 실패·학생 진입/과제
- `student-current-layout-browser-results.json`: 학생 MY·보관함·판다
- `phase2-notifications-browser-results.json`: 알림 처리
- `phase3-consent-browser-results.json`: 동의서·인증 만료
- `production-student-layout-browser-results.json`: 실제 빌드의 학생 화면
- `production-notifications-browser-results.json`: 실제 빌드의 강사 알림 화면
- 개발 서버 스크린샷은 현재 폴더, 실제 빌드 스크린샷은 `production/`에 저장했다.

재실행은 저장소 루트에서 `node 04_docs/qa/pwa-live-service-2026-09-13/run-browser-qa.mjs <검수 스크립트 파일명>`으로 수행한다.
